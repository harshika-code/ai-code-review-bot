1. Overview

AI Code Review Bot is an intelligent system that automatically reviews GitHub pull requests, detects security vulnerabilities and code quality issues, and posts actionable feedback directly on the PR.

Status: Working end-to-end — tested on a real GitHub PR, detected 2 security issues, posted review comment successfully.

Problem Statement

Manual code reviews are time-consuming, inconsistent, and often miss security vulnerabilities. Developers need an automated assistant that reviews every PR instantly.

Solution

A bot that listens to GitHub webhook events, fetches changed files, runs a review engine, and posts a Markdown review comment back to the PR — all within seconds.

3. Key Features

  • Webhook Receiver — validates GitHub HMAC-SHA256 signatures, accepts PR events (opened, reopened, synchronize)
  • PR File Fetcher — paginated retrieval of changed files with diff patches
  • Review Engine — detects hardcoded secrets, dangerous functions (eval/exec), code smells, missing tests
  • Review Poster — submits PR review comments via GitHub API
  • Dedup Logic — avoids posting duplicate reviews on the same PR
  • Manual Trigger — /review/{repo}/{pr} endpoint for testing without webhooks
  • Cloudflare Tunnel — exposes local server publicly for webhook testing

5. Setup & Installation

Prerequisites

  • Python 3.11+
  • GitHub account + Personal Access Token (classic, repo scope)
  • OpenAI API key (optional, for LLM features)

Steps

# 1. Install dependencies
pip install -r requirements.txt

# 2. Configure environment
cp .env.example .env
# Edit .env: set GITHUB_TOKEN, GITHUB_WEBHOOK_SECRET, OPENAI_API_KEY

# 3. Start the server
python -m uvicorn app.main:app --reload --port 8000

# 4. Test
curl -X POST http://127.0.0.1:8000/review/owner/repo/PR_NUMBER

### 🔒 Security issues (2)

- `test_issues.py` line 1 — This looks like a hardcoded credential. Load it from the environment instead (`os.getenv(...)` or `.env`). If it was ever committed, rotate the key — history cannot be un-pushed safely.
- `test_issues.py` line 7 — Avoid `eval`/`exec` — they run any string as code, so a user-supplied value becomes an arbitrary-code-execution hole. Use explicit functions, or `ast.literal_eval` when you only need plain data.
